# 02 — The vasm assembler (68000, Motorola syntax)

vasm (Volker Barthelmann, Frank Wille) is the reference assembler of these projects: it runs
under Linux, directly produces GEMDOS executables with their relocation table, and can be told
**not** to optimise, which makes it possible to rebuild a binary identically.

## Building

```sh
tar xzf vasm.tar.gz && cd vasm
make CPU=m68k SYNTAX=mot          # produces vasmm68k_mot (and vobjdump)
```

`scripts/get-vasm.sh` does this and installs into `.tools/vasm/`.

## Useful options

| Option | Effect |
|---|---|
| `-Ftos` | GEMDOS executable output (`.PRG/.TOS`), relocations generated by vasm |
| `-tos-flags=N` | PRG header flags word: `1` = fastload (clears only the bss), `2` = load into TT-RAM, `4` = malloc in TT-RAM. E.g. `6` to match an original game's header |
| `-no-opt` | **No optimisation** (moveq, addq, lea, short branches…): essential to reassemble a binary identically |
| `-nosym` | No symbol table in the PRG (final build) |
| without `-nosym` | DRI/GST symbol table: useful for test scripts that look up routine addresses |
| `-m68000` / `-m68030` | Allowed instruction set |
| `-Fbin` | Raw image (code to load at a given address, `org $…`) |
| `-L file.lst` | Listing: address of each instruction, for Hatari's debugger |
| `-D NAME=1` | Conditional assembly option (`ifd NAME`) |
| `-I folder` | Search folder for `include` / `incbin` |
| `-quiet` | No statistics |
| `-devpac` | Devpac compatibility mode (combine with `-no-opt`) |

Reference command for a normal program:

```sh
vasmm68k_mot -Ftos -tos-flags=1 -no-opt -nosym -quiet -o build/PROG.TOS src/prog.s
```

### Proof of the effect of `-no-opt` (verified in this repository)

For `move.l #1,d0 / moveq #0,d1 / rts`: 6 bytes of code with optimisation (`moveq #1,d0`),
10 bytes with `-no-opt`. On a rebuilt binary, such changes shift everything, break computed
jump tables and ruin the comparison with the original.

## Motorola syntax: reminders and pitfalls

- Hexadecimal: `$FF8240`; strings: `dc.b "text",13,10,0` (no C escapes).
- Short addresses above `$8000`: write them `$ffff8240.w` (sign extension); a converter from
  GNU as must turn `0xFFFF8240.w` into a negative value or `$ffff8240.w`.
- **Always make sizes explicit** (`bra.s` / `bra.w`, `move.l`, `lea …`) in a reconstructed
  source; letting vasm choose changes the bytes.
- `bra.s` too short after adding code → error: switch to `bra` (or `bra.w`).
- Bit operations: `.l` on a data register, `.b` in memory (`btst.b d0,…` is invalid).
- A local label defined twice in the same scope → error.
- A macro must be defined **before** it is used.
- `movec` (68030/040): surround with `mc68030` … `mc68000`.
- Sections: `section text,code`, `section data,data`, `section bss,bss`. A trailing bss
  takes no space in the PRG.
- Alignment: a word or long word at an odd address crashes a 68000. After any text or
  variable-length byte table, put `even`. (In one project, 274 `even` directives were added:
  they emit nothing in the original layout and restore alignment whenever a text changes length.)
- Conditional options: `ifd NAME` / `else` / `endc`, value passed with `-DNAME=1`.
- Tuning constants: group them in a file (`settings.s`) with a range-check macro
  (`CHECK_RANGE`) that stops assembly with a clear message when a value exceeds what the code
  accepts (e.g. 1 to 127 for a `moveq`).

## Devpac mode

Devpac is not available under Linux. `-devpac -no-opt` approximates its behaviour; this is a
**compatibility check**, not a guarantee: if a Devpac version is available on the Atari or in an
emulator, final confirmation must be done there. For a project delivered to Devpac users:
separate data files (`CONFIG.S`, `PATHS.S`, `TEXT.S`, `.PI1` images, `.SND` music) rather than
one big source.

## Reproducible build

Two successive assemblies of the same source must produce exactly the same bytes
(`make check` verifies it on the example). For floppy images, `tools/mkst.py` fixes the file
date (`SOURCE_DATE_EPOCH` or 2026-01-01): the SHA-256 of `build/hello.st` is identical from one
build to the next.

## Assembling code written for GNU as

A GAS source (binutils syntax) is converted to Motorola syntax by script:
`0x…` → `$…`, removal of useless suffixes (`btst.b` on a register), normalisation of spaces
after commas, negative short absolute addresses. In the project that did this, the converted
source reassembled a 91,630-byte PRG **identical to the original**, which served as proof that
the conversion was faithful.
